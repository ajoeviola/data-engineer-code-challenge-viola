                This checks three things: whether each negative-quantity row has a sale with the same store, product, customer and date, whether returns ever add up to more than was sold, and whether each return comes after its sale.

                keys = ['store_id', 'product_id', 'customer_id', 'transaction_date']
                returns = tx[tx['quantity'] < 0]
                sales   = tx[tx['quantity'] > 0]

                # 1. Does every return have a matching sale?
                m = returns.merge(sales[keys].drop_duplicates(), on=keys, how='left', indicator=True)
                print(m['_merge'].value_counts())          # 'left_only' = return with no matching sale
                unmatched = m[m['_merge'] == 'left_only']

                # 2. Do returns ever exceed what was sold for that store/product/customer/date?
                agg = (tx.assign(sold=tx['quantity'].clip(lower=0),
                                returned=-tx['quantity'].clip(upper=0))
                        .groupby(keys, dropna=False)[['sold', 'returned']].sum())
                over_returned = agg[agg['returned'] > agg['sold']]
                print(len(over_returned), "groups where returns exceed sales")

                # 3. Does the return come after the sale? (assumes transaction_id increases over time)
                first_sale = sales.groupby(keys, dropna=False)['transaction_id'].min().rename('first_sale_id')
                chk = returns.join(first_sale, on=keys)
                print((chk['transaction_id'] < chk['first_sale_id']).sum(), "returns logged before their sale")

                Things to watch for:

                Date format: if transaction_date includes a time, match on the day only. Run tx['transaction_date'] = pd.to_datetime(tx['transaction_date']).dt.normalize() first, or a return later the same day won’t match its sale.
                Missing customer IDs: for anonymous sales with no customer_id, the merge in check 1 still matches blank to blank. That could pair a return with an unrelated anonymous sale. Try returns['customer_id'].isna().sum() to see if this affects you.
                Check 3 depends on IDs being in order: it only works if transaction IDs are assigned in time order. If they aren’t, use a timestamp column instead, if you have one.
                Amounts: it’s also worth checking that total_amount is negative on return rows and equals quantity * unit_price.
